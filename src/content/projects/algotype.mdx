## What's in it

The main pool is about 7,000 LeetCode-style solutions in Python, C++, Java, JavaScript and Rust. Each one is formatted with that language's standard formatter (black, clang-format, prettier, google-java-format, rustfmt), tokenized offline and stored in Postgres. The home page serves a random short one, and Tab skips to the next.

- **Algorithms**: the main library, searchable and filterable by language and length.
- **Files**: longer real-world implementations, for endurance.
- **Syntax drills**: generated in the browser from templates (for loops, functions, classes, idioms) with random names, so they never repeat.
- **Timed**: 15, 30 or 60 second sprints on drill code.

Signing in (email, GitHub or Google) keeps your history, a WPM-over-time chart, and your theme and language settings across devices. Without an account everything still works.

## Typing code is not typing prose

The engine took the most work. A naive version breaks on the first indented line, because nobody wants to type eight spaces. AlgoType runs every file through Prism once, splits each line into tokens, and marks what's typed and what's skipped:

<TokenLine line={5} />

A few rules follow from that:

- **Indentation, comments and Python docstrings are skipped.** You type the code, not the formatting. When you press Enter, the cursor lands on the first real character of the next line, like an editor with auto-indent.
- **Errors stack.** A wrong key doesn't advance. It sits in a red buffer that you have to backspace out. A test where you can blow past mistakes measures the wrong thing.
- **One space press finishes any run of spaces**, so alignment padding doesn't punish you.
- **Lines with nothing to type disappear**, and blank lines and trailing comments don't count toward your line total.

The tokenizer is shared between the offline token builder (Node) and the browser, which is how syntax drills can be generated and tokenized on the spot.

## Under the hood

Next.js on Vercel, with Supabase for auth and Postgres. Random tests are picked by a Postgres function, so the client never loads the full challenge list. Row-level security limits each user to their own history. Profiles and history are cached in `localStorage` and checked against a `data_version` counter that a trigger bumps on every write, so returning to your account page usually costs one small query. Themes (Dracula, Gruvbox, Nord, Catppuccin, Tokyo Night and more) restyle both the site and the syntax highlighting.
